## Обязательные исправления

**TC-C01 — HIGH: adopter принимает owner decision для другого profile.** В isolated TempDir после fixture() реальный owner JSON скопирован, его profile заменён на UNAPPROVED_OTHER_LAYOUT при status APPROVED. Manifest owner_decision_sha256 и fake review inventories/digests согласованно пересчитаны, чтобы другие integrity gates не маскировали проверяемое условие. adopt() принял28-клеточный ACTION и реально изменил только временную runtime пару. Он проверяет status APPROVED и SHA JSON, но не разрешённые profile/actor/phase/budget/context/excluded scope и не канонический путь решения. Это не изменение настоящего owner approval и не настоящая ART-приёмка; fake review — намеренный отрицательный тест, как в штатном наборе. Машинный scope gate должен сам отвергать несовместимое решение, даже при согласованных остальных полях.

Исправление: потребовать канонический P06_TIMKA_SUPPORTED_ANIMATIONS.json и согласованную фактическую область решения: kind/phase/actor/profile, counts32/28/24 и total84, excluded fire/finish_sharp/finish_firearm, нужные contexts. Проверять это до backup/staging/runtime записей; добавить отрицательные тесты на другой profile/scope/budget/path. Сам исходный настоящий owner JSON просмотрен: он действительно APPROVED для timka_supported_v1/84, с оставшимися must-fix и phase/merge false. Наличие текущего правильного JSON не устраняет ошибку проверки функции.

**TC-C02 — MEDIUM: source_compaction.script_sha256 не проверяется.** Записанный digest заменён на64 нуля, а metadata/review hashes пересчитаны; реальный файл compactor и его inventory hash остаются c1a034a4247898f345aa1f9d05d0646fbeb4bd2488ea6d83e00c557cdb5d1f96. adopt() всё равно завершился. Required inventory подтверждает actual script, но не связывает его с записанным provenance digest. Это позволяет перенести заведомо ложную provenance-запись в accepted runtime metadata. Пиксельные проверки сами по себе в этом тесте не нарушены.

Исправление: канонический путь compact_timka.py и равенство recorded script_sha256 == actual file SHA == review inventory SHA до любых записей; отрицательный тест на stale/invalid digest и неверный script path. Не пересобирать арт ради исправления adopter, если original compactor/candidate bytes не менялись. Обе проблемы воспроизведены повторно против сохранённых v1 code-freeze файлов; вторая авторская версия не подменяла испытуемый код.

## Прерывание миграции

Независимые дополнительные TempDir случаи: существующий backup не перезаписывается; неполная старая runtime пара отвергается без изменения; существующий PNG staging сохраняется, runtime не меняется. В последнем случае backups создаются до staging refusal — безопасно для старых данных, но повтор уже блокируется сохранённым snapshot; это не чистая нулевая операция для source evidence.

Инъекция OSError между PNG.replace и JSON.replace оставляет new PNG + old JSON. Оба legacy backup файла точны, pending JSON сохраняется. Повторный adopt отказывает по baseline mismatch и не меняет ни одного файла fixture. Следовательно migration не транзакционна для пары файлов, не имеет автоматического rollback/resume, а fail-closed требует явного ручного reconciliation. При текущем коде legacy Timka schema1 rejected, поэтому эта смешанная пара не может служить fallback. До любого настоящего переноса нужно соблюдать отсутствие live engine и хранить backups/staging для сверки SHA; не запускать повтор вслепую.
