## Сохраняющиеся границы следующей интеграции

1. **Доверенный production scene fixture отсутствует в этой итерации.** CombatSystem проверяет форму и стабильность snapshot, но не создаёт доверие к его происхождению. TestLab.test_fixture — mutable test dictionary. Production factory/registered scene definition должны владеть actor_id/context, equipment/training grants и generation; save/UI weapon fields не могут назначать athletic_prime. Factory не должна молча создавать нового героя как legacy actor без resolver. Неизвестный/отсутствующий fixture — отказ. Actor/context switch создаёт новый fixture с reset pending contacts/effects/cost/cooldowns по manifest. Current guards отменяют старый job при смене snapshot; production reset lifecycle ещё нужно реализовать и проверить.
2. **Способности и персональные finishers не реализованы этим исправлением.** Profiles по-прежнему меняют clocks/style labels, сохраняя базовую contact semantics. Нужны отдельные механические contracts шести abilities, Input triggers, cost/ammo/cooldown/cancel/recovery, peaceful present Timka action и prime-only force, training prerequisite Olezhka, actual environmental object Tega. Catalog maximum equipment и пять drawn category contacts сами по себе этого не доказывают.
3. **Нативное управление/читаемость и новый renderer не проверены.** Новая suite вызывает `try_finisher()` напрямую; её `repeated input` label означает повтор API entry, не реальный Input replay. Даже проверка contact animation/frame использует старую Yakuza visual path. Для production нужны Input replays/captures по всем героям/четырём направлениям и context/reset/cancel paths, реальные 8-cell mappings, новые reaction/readability и synchronized contact. Жёсткий target contact frame1 (`combat_system.gd:373`) пока соответствует legacy renderer; дальнейший новый renderer требует явного mapping contract. ART/gait/camera/likeness не оценивались.
4. **Полный production once-ledger lifecycle ещё следует связать с новыми actions.** Новая suite проверяет repeated callbacks уже dead target (`character_policy_integration_test.gd:78–79`), поэтому эта конкретная assertion не изолирует receipt guard на живой цели; ранее принятый P04G suite сохраняет отдельный living-target receipt case. Общий `_apply_hit` и baseline living receipt path не менялись. Новые production ability actions должны дополнительно пройти once-hit/reward на живой цели, reset/reload/process restart, повтор callbacks и settings invariance без renderer/audio damage. Headless fixture не заменяет эти per-action доказательства.
