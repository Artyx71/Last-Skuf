Независимые отрицательные проверки C01 — ПОДГОТОВЛЕНЫ, НЕ ИСПОЛНЕНЫ.

Исполнение только после нового авторского source freeze через единственный канонический ROOT Controller.stage. Каждый startup-negative использует отдельную физическую копию game и fresh .godot, отдельные HOME/XDG/user profiles и выходной каталог. Ни одной записи в WORK, canonical state или исходные WAV. Текущие probes не сертифицированы запуском: возможную ошибку QA fixture нужно сохранить отдельно и исправить новой версией, не выдавая её за продуктовый дефект.

1. Fresh import штатной копии; registry probe (`probes/qa_c01_registry.gd`) копируется в isolated res://tests, запускается последовательно. Проверяет валидный registry, malformed root, wrong identity/context/category/path/bus, gain bool/string/null/positive/too-negative/NaN/Inf, пропущенную/лишнюю категорию, Timka present/excluded firearm/unknownactor/wrongcontext. Missing SHA metadata — наблюдение, а не требование runtime hash I/O: build/CI gate может обеспечивать строгую SHA привязку отдельно.
2. Startup probe (`probes/qa_c01_startup.gd`) в штатной копии: AYAY_C01_QA_MODE=valid, получить ready=true и реальный выбранный entry. Затем новый isolated copy для каждой отрицательной ситуации, mode=reject: base manifest с `fixture-data/base-cross-registry-collision.json`; combat_polish с `fixture-data/polish-cross-registry-collision.json`. Ожидается чистое failclosed до создания music/voice nodes, либо отдельная согласованная строгая collision policy с доказанной final binding. Тихое сохранение конфликтующего entry запрещено. В исходном WIP оба merge вызываются без overwrite; character entry проходит свою проверку, но проигрывает конфликтующему ключу базового registry.
3. Отдельные startup copy: character_finishers.json отсутствует; malformed JSON; sfx array; null entry; правильный path к отсутствующему ресурсу; коррумпированный WAV; импортированный loop-enabled WAV; длительность вне диапазона. Чистый false/ready=false, без Script Error/partially started music, затем восстановление штатных входов + ровно один успешный load, без дублированных voices/music. Стабильный штатный второй load не создаёт ещё один пул.
4. Независимый source verifier ДО accepted integration: 20 exact route/category/actor/context, exact catalog and signal decision/recipe chain, SHA WAV == accepted freeze и manifest.source_sha256; пять legacy source SHA и старые маршруты неизменны. Negative по удалению/подмене SHA, подмене WAV на другой корректный mono PCM16 0.2с и coherent-rebinding manifest к новому WAV. Нельзя принимать новую пару WAV+manifest только за внутреннюю согласованность. Если raw WAV исключены из export, эта проверка выполняется перед упаковкой, а runtime импорт проверяется отдельно. Runtime source-file SHA read не навязывается.
5. Imported AudioStreamWAV/actual selected voice: тип, loop disabled, формат/mono/mix_rate/length и фактический декодированный PCM соответствуют принятому source с документированными импортными преобразованиями. Negative stale import (source changed/cache old), wrong type/rate/channels/PCM replacement. Сам ResourceLoader.exists не доказывает эти свойства. File SHA отдельно от imported stream identity.
6. Настоящие Input→eligible Core→single contact→cue→AudioStreamPlayer/2D playback для всех20 разрешённых маршрутов +5Yakuza, own actual contact frame/time/cue/stream/bus/gain/pitch records. До contact и после отмены/смерти/reset/revoke нет ложного finisher cue; cost/damage/score остаются once. Обработчик audio_event синхронный: listener reset/free/rebind не должен порождать старый gameplay state. Reuse существующих доказанных negative Core только при точной source-equivalence; новый audio routing нужно реально проверить.
7. Реальный mixer PCM solo и на фоне музыки/нескольких контактов; ограничение12 voices, saturation/drop policy, reduced_impact фактически −5dB SFX, остальные настройки не меняют gameplay. Проверить отсутствие неожиданных тишин/клиппинга и event windows; один cue-log без playback/PCM недостаточен. Последовательно Linux native capture и позже packaged Linux/Wine, честно обозначить Wine ≠ native Windows. Source headroom не является mixer PASS.

Дополнительные carryover checks, не новые подтверждённые C01 баги: старый AudioDirector присваивает parsed base/polish в typed Dictionary до проверки shape; malformed base/polish надо считать log-fatal и фиксировать отдельно. Старый CombatProfile допускает положительные nonfinite timings (проверяется только <=0): добавить direct Dictionary/JSON negative, если формат parser способен представить Inf/NaN, и typed nested profiles negatives; не утверждать actual runtime failure до исполнения. Частое entries()/Catalog.allowed_equipment чтение в каждом resolve потенциально требует измерения при real FIN, без заявлений о FPS по статическому коду.

Полного CI command/entrypoint здесь нет: авторские runtime tests/replay ещё WIP, новый source freeze не получен. Этот файл не является PREPARED для запуска процесса. Root получает отдельный hash-bound immutable job request только после согласования финального source и последовательного расписания.
