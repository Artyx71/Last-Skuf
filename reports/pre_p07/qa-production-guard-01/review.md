# P07 production guard — независимый bounded QA v1

**FAIL_COMPONENT.** Кандидат guard не готов к установке: четыре класса проверок допускают непроверенный источник, escaped evidence или malformed approval records. Actual independent24 новых tests и47 AUTOPILOT regressions проходят, но наши10 дополнительных TempGit случаев дают6 неожиданных принятия. Это FAIL только сохранённого кандидата v1, не переоценка исторических фаз/Lead reports и не Production Readiness decision.

## Обязательные исправления

**PG-C01 / HIGH — untracked production directory symlink обходится whole-game inventory.** В позитивную frozen Git fixture добавлен game/untracked_link → external temporary directory с читаемым unreviewed.gd. Файл не входит в Git tree или approved inventory, но require_p07_production возвращает readiness=True/mission_specs21. Path.rglob не обходит symlink-каталог, а file-set включает только is_file; поэтому сам каталог не попадает в сравнение. Это отличается от tracked symlink blobs, которые git_tree уже запрещает. Исправление: явно отклонять symlink-каталоги/файлы при обходе production tree, либо безопасно включать разрешённые цели с полным root/tree/inventory binding. Не допускать невидимый source вне полного frozen game tree. Regression нужен именно для untracked symlink directory, не только обычного файла или tracked symlink.

**PG-C02 / HIGH — symlink у префикса reports/pre_p07 позволяет decision вне repository.** Обе fixture decisions перемещены в отдельный external TempDir, reports/pre_p07 заменён symlink на него. Строки относительных путей и exact recorded decision SHA остаются прежними. Оба external JSON принимаются, полный guard возвращает readiness=True. file_under проверяет принадлежность только resolved prefix, который сам может указывать наружу; resolved repository containment не проверяется. Исправление: отдельно требовать path и prefix внутри canonical root после resolve, запрещать escaping symlink ancestors; затем проверять нужный подкаталог. Проверить аналогичный planning prefix и обычные ../, absolute paths, symlink targets/loops, чтобы bad input завершался fail-closed.

**PG-C03 / HIGH — malformed severity скрывает открытый High.** OPEN finding с severity='HIGH ' принят; также принимаются severity=null и object{'priority':'HIGH'}. Код coerces value через str().upper(), проверяет только два точных текста и молча пропускает остальное. Exact 'HIGH'/OPEN контроль правильно блокируется, поэтому это обход фильтра malformed representation, а не отсутствие фильтра целиком. Исправление: валидировать тип и enum severity/status; отвергать неизвестные/пропущенные значения, либо явно нормализовать whitespace/case перед enum-check. Нельзя считать malformed finding неблокирующим Medium/Low по умолчанию. Добавить соответствующие отрицательные tests для обоих scope decisions.

**PG-C04 / MEDIUM — boolean schema=True принимается как schema1.** При прочих валидных approval полях full guard принимает JSON schema:true из-за Python True==1. Исправление: строгая проверка типа schema и известных schema values; отрицательные tests для booleans, floats/прочих malformed record types. Это отдельный contract defect, не доказательство реального независимого approval.

Все6 неожиданных принятия воспроизведены только на TEST_ONLY approvals в временных Git repositories. Ни один настоящий Lead decision/state не переписывался. Автор получил конкретные repro и начал отдельную v2 правку; этот отчёт и его исходники остаются привязаны к immutable isolated-source v1. Он не сравнивает последующую WORK v2 с v1 как будто она обязана быть неизменной.

## Что работает и что действительно запущено

Actual unittest runs в ROOT report copy: production24/24, regression47/47, exit0. Исходники обеих suites предварительно просмотрены: Controller/exclusive/workers/Git init/commit/kill используются только TemporaryDirectory fixtures; GitHub API/merge cases mocked. TMPDIR направлен в собственный ROOT reports/tmp, PYTHONDONTWRITEBYTECODE включён. Не запускались production Controller, canonical queue/state reconciliation, GitHub, engine или actual author. Все тестовые Git mutations относятся только к временным repos.

Код валидно требует canonical P06 PASS и merge MERGED с полными reviewed/merge SHA из доверенного state. Readiness inventory включает whole game tree и сравнивает actual bytes с frozen Git blobs, поэтому изменённый game файл не проходит даже после обновления claimed inventory SHA. Это подтверждено существующим новым Git fixture test, не только чтением имён. Guard не переустанавливает фактическую GitHub merge/CI authority самостоятельно: он доверяет canonical merge record, который должна формировать прежняя защищённая merge policy.

Два approval scope требуют exact decision SHA, PASS/FULL, role LEAD_REVIEWER, declared independence, непустой reviewer и P06 base binding. Missing/FAIL/BLOCKED/component/concept и отсутствие explicit authorization блокируются по штатным tests. Это проверка объявленных identity/role/independence fields; реальный отдельный Lead context обязан обеспечить workflow записи canonical approval, а не сам автор.

Для MDS проверяются ровно21 canonical chapter ID, непустые отдельные пути под planning, разные SHA содержимого, entry SHA==actual SHA==review inventory. Additional duplicate MDS через symlink отвергнут, прямой ../ inventory escape отвергнут. Содержательность и narrative/gameplay уникальность MDS остаются независимому Lead/Narrative/Gameplay; фиктивные distinct test strings не являются21 готовыми MDS.
